# Receipt extraction and normalization (RA-35 / RA-38)

`ReadabilityCheckV1` remains the RA-25 boolean gate and is unchanged. A failed gate identifies pages for a retake; a provider failure is a separate retryable or permanent adapter error. Readable but incomplete, low-confidence, suspicious or ambiguous documents continue to manager review with extraction warnings. Missing purchase fields never become a new unreadable verdict.

`ExtractionV1` remains readable for legacy records. Its runtime guard now validates provider, date, lines, numbers and confidence instead of accepting any object with a lines array. RA-5 uses a separate `ParsedReceiptV1` so incomplete lines retain nullable quantities/costs without weakening the existing complete-line contract. Both schema versions are currently 1. Unknown versions fail closed. Job references remain strings until the job suggestion scorer resolves them against a controlled catalog of immutable IDs.

## Provider contract and evidence

`createGeminiReceiptAdapter({ apiKey, model?, timeoutMs?, normalization?, fetch? }).parseReceipt(pages)` accepts an ordered array of `{pageIndex, mimeType, bytes}` and returns `{receipt, provider, model, promptVersion, usage}`. Only Gemini Flash model names are permitted; the explicit default is `gemini-3.5-flash-lite`, with prompt `ra5-receipt-v1.0`. Configuration belongs on the server. Provider payloads, credentials and transport bodies do not enter errors or logs.

The provider returns strict `ReceiptObservationV1` JSON with strings/null for quantities, amounts and dates; this avoids silently coercing malformed JSON numbers into approved costs. Domain validation rejects extra keys, out-of-bounds page references, nonnumeric confidence, unsupported versions and malformed shapes. Each non-null field should have a text snippet, page index and confidence. Missing evidence or confidence becomes a review warning.

Array size caps (100 lines, 100 job hints, 1,200 evidence entries) are enforced by the domain validator. They are deliberately omitted from the provider JSON schema: a live Gemini Flash check on 2026-09-08 rejected the nested schema with those large `maxItems` values as `INVALID_ARGUMENT`; the same request passed after removing only those schema maxima. Runtime limits and strict validation remain unchanged.

`ParsedReceiptV1` holds normalized fields, all incomplete material lines, per-field confidence, document and line job hints, warnings and original evidence. Original strings are preserved under `original_observation` even when arithmetic or parsing rejects them. **`raw_text`, evidence text and `original_observation` are restricted receipt evidence and must be stored in the private evidence record, not operational logs or a general manager payload.** Persist actual returned model version, configured prompt version and schema version with the immutable extraction record. Reprocessing appends a record; it never rewrites evidence or manager decisions.

The adapter sends the pages in one request, in capture order, requesting one combined receipt with continued material lines. Each line retains its page and original source index. It must not collapse two actual identical purchases. Image orientation is normalized by the queue worker before invoking the adapter. For bodies beyond the conservative 19 MiB inline budget, it uploads temporary Gemini files, preserves order and deletes them in a bounded cleanup step on success or failure.

The default whole attempt timeout is 90 seconds with up to 5 seconds for file cleanup. HTTP 408/504, 429, 5xx, network errors and invalid/empty JSON are retryable. Authentication/configuration/request rejection, safety refusals and truncated output are permanent actionable failures. The queue owns retry count/backoff and lease renewal; the adapter never loops on errors. Safety and truncation cannot be mistaken for a valid partial extraction.

## Deterministic interpretation

- The tenant locale is USD with a decimal point and optional correctly grouped thousands commas. Missing currency uses this explicit USD tenant convention. `$` and `USD` are accepted; unsupported explicit currencies produce null costs and a warning. No foreign currency conversion is performed. Money must have at most two decimal places, is stored as integer cents, and is bounded by the existing signed 32-bit review amount limit.
- Quantities must be positive decimals with at most three decimal places. Negative/credit values are preserved as observations and flagged as deferred return support. Unknown units remain visible with a warning; recognized aliases normalize to `ea`, `ton`, `yd3`, `ft`, `ft2`, `lb`, `gal`, `bag`, `box`, `can`, `hr` or `yd`. No physical quantity conversion is inferred.
- ISO dates and unambiguous four-digit-year numeric/month-name dates are supported. Numeric dates with competing month/day interpretations and two-digit years remain null with an ambiguity warning. A verified vendor convention can explicitly provide `dateOrder: "MDY" | "DMY"`; the model cannot choose that policy. Invalid calendar dates never roll over silently.
- Application code multiplies quantity thousandths by unit cents using integer arithmetic and rounds half-up, matching RA-4. Printed extended amounts remain references. Missing quantity/unit cost remains null; there is no assumed quantity one or derived unit cost. Material totals stay null if any retained line has an unknown calculated amount.
- Header tax and total never alter material unit/extended costs. Exact tax/payment/summary line labels are excluded if the provider incorrectly emits them as charge lines. A one-cent default tolerance flags line, subtotal and total mismatches; tax-inclusive receipt reconciliation requires a known tax reference. Discounts/fees and missing lines can therefore remain visible mismatches for a manager to resolve.
- Picking lists and unknown document kinds always have a document-review warning. Low confidence (default below 0.7), unknown units, missing evidence, missing required fields and invalid values are retained for review rather than silently repaired.

## Verification boundary

Unit regressions cover distinct synthetic Select, Sandman, Klumm, Menards, Lowe's, Home Depot and Perrysburg Pipe field formats, decimal tonnage, UOM variants, continuation pages, confidence, invalid inputs, tax exclusion and amount mismatches. Adapter tests cover structured requests, runtime validation, Files API cleanup, ordered pages, timeouts and classified failures. These tests verify application behavior and the mocked provider boundary. Real-vendor layout/extraction accuracy and real Housecall job assignments or synchronization remain explicitly deferred. No provider benchmark or RA-36 implementation is included.
